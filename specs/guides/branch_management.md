# 分支管理说明

本文档约定 MyAgents 的功能开发、版本规划和分支记录方式。

---

## 分支命名

| 分支 | 用途 | 示例 |
|------|------|------|
| `main` | 主干，保持最新 release 代码 | `main` |
| `feature-*` | 功能特性分支 | `feature-login-static` |
| `xiaoce_vn.n.n` | 版本分支，`n` 为自然数 | `xiaoce_v0.0.1` |

---

## 开发流程

### 1. 创建特性分支

所有特性分支都从最新 `main` 创建：

```bash
git checkout main
git pull
git checkout -b feature-login-static
```

### 2. 创建版本分支

开始一个版本规划时，从最新 `main` 创建版本分支：

```bash
git checkout main
git pull
git checkout -b xiaoce_v0.0.1
```

### 3. 合入计划内特性

特性开发完成，并确认进入当前版本后，合并到版本分支：

```bash
git checkout xiaoce_v0.0.1
git merge --no-ff feature-login-static
```

默认使用普通 merge，并建议带 `--no-ff`，保留特性分支的合入边界。默认不使用 squash merge。

### 4. 调整版本规划

版本分支只合入确定进入该版本的特性。

如果特性未完成、风险过高或决定延期，不合入当前版本分支，记录到后续版本规划中。

---

## 版本规划记录

创建版本分支、合入特性、延期特性时，都需要同步更新记录。

| 版本分支 | 版本状态 | 特性名称 | 特性分支 | 合入状态 | 合入 commit | 延期版本 / 备注 |
|----------|----------|----------|----------|----------|-------------|-----------------|
| `xiaoce_v0.0.1` | 开发中 | 静态登录资源 | `feature-login-static` | 已合入 | `6a9f0e5` | 当前版本包含 |

### 状态建议

| 字段 | 建议值 |
|------|--------|
| 版本状态 | `规划中` / `开发中` / `测试中` / `已发布` |
| 合入状态 | `未合入` / `已合入` / `延期` / `移除` |

---

## 检查清单

发布版本前确认：

- 版本分支只包含本版本确定发布的特性。
- 每个已合入特性都有对应的特性分支记录。
- 延期或移除的特性已记录原因和后续版本。
- 版本规划记录与实际分支合入情况一致。
